# 图表制作与分析口径

本阶段使用只读清洗库，图表配置版本 `0.3.0`。遵守 `图表规范.md` 与 `../theme/SKILL.md`，
主题字号及单色连续色板沿用初始化记录的适配说明。数据集03为主分析；数据集02仅用于范围对照，
不把不同来源的账号合并成独立人数。

## 完整脚本与运行

在本项目目录安装 `.[analysis,viz]` 依赖，使用开源中文字体 Noto Sans SC 或思源黑体：

```powershell
python -m genshin_insight charts
python -m genshin_insight charts
```

未安装包时设置 `$env:PYTHONPATH = 'src;.'`。六行入口通过本地 import 调用：

```python
from genshin_insight.charts import generate
output = generate()
```

文件位置使用 `pathlib`；连接生命周期用 `contextlib`；不依赖 `os` 或修改 `sys.path`。
按工程规范第2、5、12条拆分：`ads.py` 管聚合保护，`viz/plots.py` 管图形，`charts.py` 管运行与发布。
所有模块被 import 时不读业务文件、不连接库、不创建目录、不加载 Matplotlib。

默认选择 `data/genshin_clean_*.db` 中修改时间最新的文件；可用 `--database` 指定。
自定义 `--output` 必须是本项目内部尚不存在的目录；不会覆盖旧图集。输入库使用 SQLite 只读模式、
query_only 和列允许清单，读取清洗稽核确认通过后再分析；不访问源库、UID、抽卡ID、源路径或JSON/BLOB。

## 八张图的口径

| 图 | 回答的问题 | 聚合与限制 |
| --- | --- | --- |
| Q01 数据集范围 | 主来源占多少，两个来源规模如何 | 来源内账号去重；抽数与账号数分面，不使用双轴 |
| A01 卡池构成与五星占比 | 记录集中在哪个池，各池记录内五星占比多少 | 301/400按角色活动池合并；不同指标分面；不是官方概率 |
| A02 卡池月度记录 | 哪些月份留存抽数较高 | 按库中时间自然月聚合；各池独立纵轴并明示；缺失不插值；起止月可能不完整 |
| A03 星期小时热力矩阵 | 留存记录集中在哪个星期和小时 | 7×24格累计抽数；单粉色阶、格内数字；时区和曝光天数未知，不推算活跃 |
| A04 账号留存记录量 | 分布、典型记录量和累计占比如何 | 账号内合并各池；固定箱、稀疏相邻箱合并；不展示个人散点，不换算付费 |
| A05 账号记录量分组五星占比 | 不同记录量组的账号分布如何 | 各池分别按抽数四分组、重复边界合并；账号等权中位数和四分位区间；不是置信区间 |
| A06 记录内五星间隔 | 两次已记录五星之间相隔多少条 | 排除池内排序歧义账号池；五星序号差；排除首个五星前段与未闭合尾段；无法识别缺失历史 |
| A07 五星原始名称记录榜 | 哪些原始名称出现次数多 | 精确原始名称汇总；不合并翻译别名，不使用待复核类型；不是角色人气榜 |

Q01仅保留在内部图集，分析报告与HTML答辩不展示该章节；主分析的样本数和日期仍作为必要统计口径说明。

所有柱、横条的数据起点均为0；标签栏置于框内。统一蓝粉语义、稳定卡池色、开源字体、
严格16:9、3200×1800像素、200 dpi；标题含计算得到的数字，副标题写口径，来源写脚本、配置哈希及清洗规则版本。
`viz.finish()` 统一在标题上方添加主色短条，保留标题、轴区和来源行左侧对齐。

## 小样本与对账

聚合发布门槛为5个贡献账号。不足门槛时，ADS将指标和贡献人数都置空；若一个可加分区只有一个隐藏格，
再隐藏另一格，图上统一显示抑制或缺口。月度按卡池分区保护，不通过卡池总量反推出单格。
分布合并相邻区间再发布，累计曲线仅基于合并后的安全分箱。

月度和名称汇总中，同一账号可能跨天、星级、物品ID或原始卡池代码出现，因此不累加已有去重人数，
以已有格内人数最大值作为贡献人数保守下界；间隔合箱也取最大贡献人数作为下界。
这种方法可能额外合并或隐藏实际人数足够的格子。各池间隔分别合箱，每箱都达到门槛才发布，
各面板直接标出最终区间边界，不能假设三个池的尾部箱宽相同。
不发布任何账号ID、逐账号指标或样本明细。

账号抽数总量与来源总量、分箱账号数与来源账号数必须对账一致。保存前执行主题禁止项自检，
并额外检查数字标题和16:9。合成测试图不作为分析交付；正式图全部由真实受保护聚合生成。

## 产物与复现边界

`image/analysis_<运行编号>/` 包含八张PNG、受保护的 `ads.json`、`分析报告.md` 与 `manifest.json`。
清单记录参数、配置哈希、代码SHA256、输入文件名/大小/修改时间、Python/Matplotlib/NumPy/pandas版本和实际字体。
文件元信息用于区分本地输入，并非全库内容校验哈希。图集只描述给定公开记录，不作因果推断、
官方概率或保底承诺，不在父目录或版本库发布数据与生成图。

## HTML答辩制作

`python -m genshin_insight defense --analysis image/analysis_20261019_final` 从既有ADS与清洗聚合稽核制作32页答辩。
通过本地import复用 `viz/plots.py`，主题自检后保存七张SVG；命名空间隔离图元ID，文字仍为可编辑SVG文本。
图表、子集化WOFF字体、SIL字体许可、翻页脚本和逐页讲稿全部内嵌到单个HTML，不依赖CDN或网络请求。
演示采用原主题色彩与字体；正文使用更适合投影的字号，图表保持16英寸主题基准。

产物位于已忽略的 `reports/`，包含 `index.html`、`讲稿.md`、`build_manifest.json` 与可复用矢量附件。
导航栏默认隐藏，按H显示或再次隐藏；支持方向键、目录、讲稿、全屏、触屏翻页及16:9打印。浏览器检查脚本为 `test/contract/check_defense.cjs`，
需要本机Playwright和Chrome；测试截图与打印预览只写本项目 `.pytest_cache/`。

答辩配置1.1.0将最后一页改为只含THANKS，移除该页提问、来源与页码。
`speech.py`维护32页完整口播与术语附录，同步写入Markdown及HTML页内讲稿；附录不增加幻灯片。
Q1～Q4为按抽数排序的账号组，P25/P50/P75为组内比率的分位点，IQR为P75减P25；这两套记号不能混用。
默认仍拒绝覆盖输出；用户明确要求修改既有演示时，可对含构建清单的目录使用 `--replace`。

## 开场短片

`python -m genshin_insight opener`只复用同次受保护ADS与聚合清洗稽核，制作40秒图表与1.2秒入门白场，
成片为1080p、60fps的H.264/AAC MP4。指定夜间开门视频同时提供背景与原声，取消旧背景动效和原创配乐。
图表前景在39.6–40秒淡出，40秒起清空；全部白屏后自动进入既有32页HTML答辩。
图表保留金色强调，报告和PPT保持蓝粉主题。统计图保持单轴、零基线与原始聚合语义，
数字由代码计算，保留来源和关键解释边界。

本地Chrome逐帧导出透明图表，由FFmpeg叠加60fps背景、封装同段原声；采用CRF 23 / slow和AAC 160k压缩。
编码后完整解码校验，并在浏览器检查时长、分辨率、文本安全区和自动进入答辩的流程。
QA截图与日志存于项目 `.pytest_cache/`。构建中间文件也只写项目缓存，正常构建结束后自动清理。
交付目录仅包含成片、入口、海报、说明、清单及字体许可；原始数据与构建缓存不提交。
